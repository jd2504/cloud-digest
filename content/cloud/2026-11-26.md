## Provider announcements

### AWS

**Elastic Load Balancing for Envoy.** Status: GA (November 25), in 14 regions across the US, Europe and Asia Pacific, including N. Virginia, Ohio, Oregon, Ireland, Frankfurt, Tokyo, Singapore, Mumbai and Sydney. This is a new ELB type that runs open-source Envoy proxies on dedicated, Nitro-isolated EC2 instances. AWS takes care of capacity across Availability Zones, watches for CVEs and applies Envoy and OS patches. You can extend it with WebAssembly, Lua or external processing. Envoy Gateway users can move over through a remote infrastructure provider without rewriting their Gateway API resources. AWS says it supports each Envoy version for two years. The announcement excerpts we saw give no pricing. Why it matters: teams that run their own Envoy fleets for advanced L7 routing can hand off upgrades and patching while keeping Envoy's configuration model. ALB and NLB are still the simpler choice for standard load balancing. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/elastic-load-balancing-for-envoy-generally-available/); [AWS product page](https://aws.amazon.com/elasticloadbalancing/elbproxy/))

**API Gateway API Portal and AWS WAF API and AI security.** Status: GA (November 23). API Portal builds an ongoing inventory of APIs behind API Gateway, ALB and CloudFront across an AWS organization, using traffic logs and configuration records. Every endpoint starts out marked "shadow" until someone governs it. The portal labels LLM, MCP and A2A endpoints, flags APIs that have gone idle or lost their owner, and checks posture (authentication, throttling, WAF coverage). It is available in 32 regions. Alongside it, new WAF managed rule groups protect what the portal finds. The AI Security group validates MCP and A2A (version 1.0 only) messages against their protocols and sends content to Bedrock Guardrails to check for prompt attacks, harmful content and sensitive data. By default it blocks high-severity prompt attacks. If the Guardrails call fails, the request goes through unless you change a rule to block it. Pricing: AWS says WAF pricing changes on February 1, 2027, adding an API and AI security fee for each inspected request. Why it matters: shadow MCP servers and agent endpoints are a new attack surface, and this gives you discovery and inline inspection at the edge. Check the limits before relying on it: Bedrock's own runtime APIs aren't recognized, and model completions aren't checked for prompt attacks. ([AWS — API Portal](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-api-gateway-announces-api-portal/); [AWS — WAF AI security](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/); [AWS Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/))

**IAM trusted identity propagation now covers IAM federation and IAM Roles Anywhere.** Status: GA (November 25), in all commercial regions, GovCloud (US) and the European Sovereign Cloud. Role sessions created through SAML/OIDC federation can now carry the original human or workload identity, plus optional runtime claims. For Roles Anywhere, the identity comes from the certificate subject. That context follows the session through chained role assumptions within the same organization, and it is dropped when a session crosses into another organization. Trust policies don't need the sts:SetContext permission. It is on by default for new IAM identity providers. Why it matters: CloudTrail and authorization policies can now see who is behind a shared role, which closes a long-standing audit gap in federated and on-premises workload access. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/); [AWS Security Blog](https://aws.amazon.com/blogs/security/know-the-identity-behind-the-role-authorize-and-audit-with-trusted-identity-propagation/))

**Lambda durable functions can orchestrate Lambda MicroVMs.** Status: developer preview (November 25), for the TypeScript and Python Durable Execution SDKs, in regions that support both features. AWS says not to use it for production. A durable function can now start, run work on and tear down MicroVMs (Firecracker-isolated environments that keep state for up to eight hours) as checkpointed durable steps. It can run several MicroVMs in parallel or a session in which tasks share files and memory. Retries and token refresh are handled for you. Why it matters: it is a serverless pattern for running untrusted or agent-generated code (CI jobs, scanners, "software factories") with VM-level isolation, without building your own orchestrator around sandboxes. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/lambda-durable-microvm/))

**EC2 G7 instances get a bare-metal size.** Status: GA (November 23), in N. Virginia only, as On-Demand, Spot or Savings Plans. The metal size has 8 NVIDIA RTX PRO 4500 Blackwell GPUs (32 GB each), 192 vCPUs, 768 GiB of memory and 700 Gbps of EFA networking. Why it matters: AWS pitches it for physical-AI simulation, agent sandboxes and workloads that need their own hypervisor or GPU drivers. That is a use case virtualized GPU instances couldn't cover. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-g7-metal-size/))

### Google Cloud

**Workspace MCP servers and Workspace CLI, with new agent governance.** Status: GA (announced November 25), rolling out to all domains over about two weeks. Google now hosts MCP servers for Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat and Tasks. They include permission and DLP checks, required user confirmation before sensitive actions such as sending mail or changing sharing, and they reject OAuth clients that aren't registered as agents. A Workspace CLI with JSON output covers local agents and scripts. Under new terms, agents must use the MCP servers or the CLI instead of the REST APIs, with technical enforcement starting February 1, 2027. A free Standard usage tier comes with published quotas, and billing for the higher Scaled tier starts April 1, 2027. On the Cloud side, Google described Agent Gateway, which checks agent identities against Agent Registry, applies IAM policies and default-deny egress, and screens traffic with Model Armor. Its documentation lists it for Agent Platform and GKE agents, and as limited preview on Cloud Run and outside Google Cloud. Why it matters: if you have agents that use Workspace through REST today, you now have a migration deadline and a future cost line. ([Google Cloud](https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise); [Google Workspace Updates](https://workspaceupdates.googleblog.com/2026/11/mcp-servers-cli-standardized-usage-tiers-now-available.html))

**BigQuery cross-cloud connections to AWS, Azure and Salesforce Data 360.** Status: GA (November 25), from all BigQuery regions. Instead of an Omni location, you pick a standard BigQuery location near the AWS or Azure region where the data sits. Google says these connections support more BigQuery features and cost less than standard BigQuery Omni connections. Why it matters: analytics on data that stays in S3 or Azure storage no longer has to be limited to Omni's feature set. That makes "query in place" a more realistic alternative to copying data between clouds, though egress and latency still need planning. ([Google Cloud release notes](https://docs.cloud.google.com/release-notes); [Google Cloud docs](https://docs.cloud.google.com/bigquery/docs/cross-cloud-connections))

## Industry news

**Microsoft declares an internal "Code Red" after its Microsoft 365 outage.** Reuters reported internal memos describing a priority program with five workstreams after the November 12–13 Exchange Online outage. The workstreams include load shedding, geographic partitioning of traffic and faster recovery, and the goal is to resolve future worldwide incidents within an hour. SiliconANGLE's coverage adds that Microsoft again ruled out a cyberattack as the cause. For architects, these are the same fixes most large SaaS platforms eventually adopt: smaller blast radius through partitioning, plus deliberate load shedding so a partial failure doesn't take down the whole fleet. ([SiliconANGLE](https://siliconangle.com/2026/11/24/microsoft-declares-internal-code-red-after-nearly-24-hour-microsoft-365-outage/); [The Register](https://www.theregister.com/saas/2026/11/23/microsoft-mega-outage-report-reveals-testing-gaps-and-emails-that-never-arrived/5311656))

**US adds GPU-cloud firm Megaspeed and six affiliates to the Entity List.** BIS added seven entities in Malaysia, Singapore and Thailand, effective November 23 and published in the Federal Register on November 25, citing a significant risk that advanced computing chips would be diverted. Exports to them now need a license, with applications presumed to be denied. Commerce and Justice issued a joint statement saying DOJ is leading a criminal investigation. Megaspeed denies wrongdoing. Semafor broke the story. For anyone using Southeast Asian GPU capacity, this is another reminder to check your providers' export-control exposure. ([Federal Register](https://www.federalregister.gov/documents/2026/11/25/2026-23999/additions-to-the-entity-list); [Commerce](https://www.commerce.gov/news/press-releases/2026/11/joint-statement-department-commerce-and-department-justice-megaspeed); [The Register](https://www.theregister.com/systems/2026/11/24/us-blacklists-megaspeed-hours-after-jensen-huang-returns-to-nvidia/5311901))

**Radware Cloud WAF breach exposed customers' log-export cloud keys.** Radware says that on November 19, an attacker reached an internal Cloud WAF management API that was exposed to the internet without authentication. The attacker got customer contact details and, for some customers, the credentials Radware uses to export logs to their S3, Azure Blob and SFTP storage. Radware told affected customers to rotate those credentials and review storage access logs back to November 19. Some customers had already seen AWS alerts about an unknown IP probing their log buckets. Radware says traffic inspection and certificates were not affected. The lesson: every credential you give a security vendor to write into your account should be least-privilege, write-only and scoped to one bucket or prefix. ([BleepingComputer](https://www.bleepingcomputer.com/news/security/radware-discloses-breach-exposing-customer-cloud-access-keys/))

**Rackspace will shut down Spot after its Kubernetes breach.** After the November 17 intrusion we covered on Monday, Rackspace told customers it is closing the low-cost Spot Kubernetes platform. Customers must move workloads and download data by December 8 at 5 p.m. Central, and should treat API tokens, refresh tokens, kubeconfigs and Secrets as compromised. Some customers have asked Rackspace to raise prices rather than close the service. Two weeks' notice is a hard test of portability, and teams that run plain Kubernetes manifests with an external secrets manager will have the easiest move. ([BleepingComputer](https://www.bleepingcomputer.com/news/security/rackspace-shuts-down-spot-cloud-platform-after-security-breach/))

**Broadcom patches 23 VMware flaws, including a CVSS 9.8 vCenter authentication bypass.** VMSA-2026-0011 (November 24) covers ESX, vCenter, Workstation, Fusion, Tools and Avi. The critical issues are an unauthenticated authentication bypass in vCenter's directory service (CVE-2026-123903) and two ESX I/O-filter memory bugs. Broadcom says there is no workaround, and ESX patches can't be live-patched, so hosts must reboot. It is the third critical VMware patch bundle in a week, after a vCenter zero-day the week before. Private clouds and VMware-based hosted environments (such as AVS, GCVE and OCVS) should check their providers' patch timelines. ([Broadcom](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/0/39626); [VMware on GitHub](https://github.com/vmware/vcf-security-and-compliance-guidelines/blob/main/security-advisories/vmsa-2026-0011/README.md); [The Register](https://theregister.com/virtualization/2026/11/25/this-could-mess-with-thanksgiving-says-vmware-as-it-drops-third-critical-patch-bundle-in-a-week/5312017))

## Architecture & design patterns

### Scaling Git for coding agents: OpenAI's Pando

*OpenAI engineering blog; InfoQ coverage, November 24.* OpenAI describes Pando, a Git-compatible backend built for thousands of agents pushing at the same time. Clients and the Git protocol stay the same. Underneath, pushes stream packfiles to blob storage, branch updates are coordinated independently so unrelated branches don't contend, and stored packs are reused across fetches. OpenAI reports a nearly 80% cut in median push latency in production. The tradeoff is that readers no longer get a consistent snapshot of the whole repository. InfoQ notes that some of the scaling figures come from synthetic models, not production benchmarks. **When to use it:** when agent-driven CI or code generation turns your source-control server into a write-contention hotspot. The core idea is to give up global consistency where no workflow needs it. ([OpenAI](https://openai.com/index/scaling-git-at-openai/); [InfoQ](https://www.infoq.com/news/2026/11/openai-git-pando/))

### Splitting coordination from computation: DoorDash's dispatch redesign

*DoorDash Engineering; InfoQ coverage, November 25.* DoorDash replaced a monolithic optimization engine with a stateful coordinator that owns dispatch lifecycles and global state, plus stateless workers that run optimization, routing and model inference. Problems are split by geography and delivery trajectory, solved in parallel, and merged by a reconciliation layer. The team rolled it out by shadowing production traffic: the old engine kept making assignments while the new system's results were logged for comparison. DoorDash reports 10x throughput and availability above 99.99% at peak, including Super Bowl Sunday. **When to use it:** when a central optimizer or scheduler can no longer scale vertically. Partition the problem, keep only coordination stateful, and use shadow traffic to cut over safely. ([DoorDash](https://careersatdoordash.com/blog/how-doordash-built-a-next-generation-real-time-dispatch-platform/); [InfoQ](https://www.infoq.com/news/2026/11/doordash-dispatch-redesign/))

Little else of note was published in the holiday-shortened window, so this section is short.

## Takeaway

Before re:Invent, providers are treating AI agent traffic as something to manage like any other enterprise traffic. AWS now finds and inspects MCP and A2A endpoints at the edge and traces the person behind federated role sessions. Google requires Workspace agents to use governed MCP servers and puts Agent Gateway in front of agent egress. Meanwhile, this week's incidents were all control-plane failures: an unauthenticated Radware management API, stolen credentials at Rackspace Spot, a 9.8 vCenter authentication bypass, and a Microsoft outage that spread fleet-wide. The common lesson for architects is to inventory every management and agent endpoint, scope the credentials behind each one tightly, and keep the blast radius small.
