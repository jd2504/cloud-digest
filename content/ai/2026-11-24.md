## Model & platform announcements

### Anthropic

**Claude Ship: agents that review, fix and approve pull requests**
- Status: beta (November 23). Claude Ship bundles Code Review (already GA), PR Steward (beta) and Claude Approvals (beta), plus a `/ship` command rolling out in Claude Code and the desktop app.
- What it does: PR Steward works on failing CI checks, merge conflicts and review comments and pushes fixes. Claude Approvals applies a merge policy written in natural language and stored as a file in the repository. That policy can use Code Review findings and an organization's own classifiers, and can run in observe-only mode first.
- Availability and pricing: Claude Team and Enterprise plans, GitHub repositories only. It is not offered to organizations using zero data retention, the HIPAA configuration or customer-managed keys. Billing is per token, and cost scales with PR volume, review depth and PR Steward activity. Admins can cap spend for Code Review and PR Steward. Approvals has no base fee, but classifiers and any Code Review a policy triggers are billed, including in observe mode. Eligible Enterprise organizations can claim at least $10,000 in credits by January 15, 2027.
- Why it matters: this moves an AI agent from suggesting changes to deciding what merges. Treat the policy file like branch protection: version it, review changes to it, run it in observe mode, and set spend caps before turning it on for busy repositories. ([Anthropic](https://claude.com/de/resources/articles/introducing-claude-ship); [SiliconANGLE](https://siliconangle.com/2026/11/23/anthropics-claude-ship-automates-the-final-stage-of-the-software-development-pipeline/))

**Zero data retention with Enterprise Frontier Safeguards**
- Status: public beta (November 23), after a private beta. Access is not self-serve. Anthropic notifies eligible customers with setup steps.
- Availability: Claude Platform, Claude Platform on AWS, Amazon Bedrock and Claude on Google Cloud. Microsoft Foundry support is listed as coming soon. No separate price is stated, and the customer's own S3 or Cloud Storage bucket is billed by its cloud provider as usual.
- How it works: abuse monitoring that looks across many requests runs against data in the customer's own bucket, so neither Anthropic nor the cloud provider retains prompts or outputs, and there is no human review by the operator. Findings come back as "Safety Cases" that can be read from storage or an API and sent to a SIEM.
- Why it matters: regulated teams that need zero retention have had trouble getting access to the most capable, most tightly monitored models. This is the path Anthropic is offering. Plan for a bucket, IAM grants and SIEM routing. ([Anthropic](https://claude.com/resources/articles/zero-data-retention-with-enterprise-frontier-safeguards))

**Also announced**
- **Computer use (beta) for Claude Team and Enterprise plans** is rolling out gradually in Claude Desktop, and on web and mobile where admins have turned on computer access. Security teams should review that setting before it reaches users. (November 20) ([Claude Help Center](https://support.claude.com/en/articles/12138966-release-notes))

### Google

**Gemini 4 Neon (`gemini-4-neon`), launched November 18 and missed in the last issue**
- Status: rolling out on the Gemini API paid tier in AI Studio and in Gemini for business. Google's post gives no GA or preview label. A cyber variant is going to members of Google's Fairwind Program.
- Pricing: $3 per million input tokens, $0.15 cached input and $15 output, with a 1M-token context window. That is below the $4/$20 list price Carbon and Argon move to on December 1.
- Positioning: Google places Neon between Carbon (long tasks) and Hydrogen (fast, everyday work), and pitches it as an agent orchestrator that hands work to Hydrogen subagents. The company reports a 61 on the Artificial Analysis Intelligence Index at xhigh thinking, 65.2% on Terminal-Bench 4.1, and about 32% lower cost per task than Carbon. These are vendor figures, and the post gives no method.
- Why it matters: for coding and tool-heavy agents now on Carbon or Argon, Neon is the obvious test before the December 1 price rise. ([Google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/); [The Register](https://www.theregister.com/ai-and-ml/2026/11/19/google-continues-model-chemistry-experiment-with-neon/5310934))

**File slicing controls in the Gemini API**
- Status: available now via the API (November 23), with no GA or preview label. It works across all Gemini 4 models in AI Studio and on Google Cloud. Billing covers only the parts the model reads, and existing size and page limits still apply.
- What it does: requests can name PDF or Office page ranges (`start_page`, `end_page`), spreadsheet sheets and cells (`sheet_index`, `visible_cells`), audio and video clip offsets (`start_offset`, `end_offset`), and a resolution. The API also now accepts Microsoft Office and OpenDocument files directly. Agents can set slices inside a function response.
- Why it matters: agent harnesses can stop running LibreOffice, PDF renderers or ffmpeg just to cut a file down before sending it. Partners Vercel and LiteLLM report large prompt-token reductions; Google cites them, but they are not independent measurements. ([Google](https://blog.google/innovation-and-ai/technology/developers-tools/file-slicing-controls/))

### OpenAI

No new API models, pricing changes or deprecations were posted in the window. Deadlines announced earlier are close:
- **November 30:** `/v1/prompts` and reusable prompt objects, the Evals dashboard and API, and Agent Builder shut down. OpenAI points to application code for prompts, Promptfoo for evals, and the Agents SDK or ChatGPT Workspace Agents for Agent Builder.
- **December 1:** `gpt-image-1-mini`, `gpt-image-1.5` and `chatgpt-image-latest` retire. The replacements are `gpt-image-2.6-sunburst` or `gpt-image-2.6-flare`.
- **December 11:** `gpt-5`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5-pro`, `o3` and `o3-pro` retire. The named replacements are `gpt-6.1-sol` (with `reasoning.mode: pro` for the pro models), `gpt-6.1-terra` and `gpt-6-luna`. ([OpenAI](https://developers.openai.com/api/docs/deprecations))

### Thinking Machines Lab

**Inkling 2 Mini (`thinkingmachines/Inkling-2-Mini`), open weights**
- Status: released November 20 as open weights under Apache 2.0.
- Specs: a multimodal mixture-of-experts model with about 26B total and 3B active parameters. It "loops" a 12-layer core block three times per token and has a 1M-token context. It takes image and text input, and quantized builds fit in about 32GB, enough for a laptop or a single desktop GPU. It is supported in transformers, llama.cpp, MLX and SGLang on day one.
- Pricing: VentureBeat reports $0.15 input and $0.50 output per million tokens on Thinking Machines' own API, and lower rates on OpenRouter. Benchmark claims are the company's.
- Why it matters: a permissively licensed, long-context model that runs on one machine is a serious option for on-device or air-gapped agents, and a cheap tier to route easy calls to. ([Hugging Face](https://huggingface.co/blog/inkling2mini); [VentureBeat](https://venturebeat.com/technology/thinking-machines-wows-with-inkling-2-mini-looped-transformer-model-that-runs-locally-on-laptops))

### Model platforms

**Amazon Bedrock: Web Search adds languages and country-aware results.** Status: available (November 21), applied automatically with no code changes. Web Search on Bedrock and AgentCore now handles Spanish, French, German, Italian, Japanese and non-US English, at the same price in every language. A new optional field takes an ISO country code to localize results. The AgentCore version runs in six regions (N. Virginia, Ohio, Oregon, Sydney, Tokyo, Ireland), and the Bedrock version in US regions only. Why it matters: grounded agents serving users outside the US no longer need a third-party search API to get local results. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/web-search-amazon-bedrock/))

### Protocols & open source

**Shirudo: OpenAI and Cisco's open-source runtime for blocking exploits before a patch lands**
- Status: open source (November 23). The code is BSD 2-Clause, and its eBPF programs are dual-licensed BSD/GPL. Some capabilities are described as design goals rather than shipped features.
- What it does: Shirudo loads signed eBPF "shields" into a running Linux system to block a vulnerable code path while a real fix is prepared, with a TPM-backed record of each load and removal. In OpenAI's one controlled demo, a shield written by Codex added an input check to Java's Base64 decoder and stopped an exploit against a live Elasticsearch process without a restart.
- Why it matters: it pairs AI-written mitigations with signing and audit. That is the control you would want before letting an agent push live hot-patches. Treat it as early-stage. ([OpenAI](https://openai.com/index/introducing-shirudo/))

## Industry & policy news

**Amazon agrees to buy Decart's inference-optimization technology and team.** Amazon announced on November 23 that it will acquire the technology behind the Decart Optimization Stack and bring over its co-founders and engineers, subject to regulatory clearance. The stack makes models run faster on Nvidia, Trainium and Google hardware. Amazon disclosed no terms. TechCrunch, citing Bloomberg, puts the price at $7.5 billion and ties the deal to Amazon's plan to sell Trainium chips to outside customers. For architects, this points to more model-portability tooling for Trainium on Bedrock and SageMaker. ([Amazon](https://www.aboutamazon.com/news/company-news/amazon-decart-ai-optimization); [TechCrunch](https://techcrunch.com/2026/11/23/amazon-snaps-up-decarts-ai-optimization-tech-for-7-5b-as-it-prepares-to-sell-trainium-chips/))

**OpenAI's chief scientist proposes perplexity as a shared yardstick for limiting AI development.** In a November 22 post, Jakub Pachocki publishes OpenAI's internal pretraining loss figures: about 0.91 for GPT-4, under 0.8 for recent models, and about 0.76 for the model that began producing results on open math problems. He proposes that labs agree on "common limits" measured this way, and expects new capabilities as losses approach roughly 0.68–0.70. It is a proposal, not a policy, and the post lists the metric's weaknesses, including that loss on different datasets is not comparable. It is a sign of the kind of compute-and-capability threshold regulators may borrow. ([OpenAI](https://openai.com/index/perplexity-and-intelligence/); [TechCrunch](https://techcrunch.com/2026/11/22/openais-chief-scientist-has-thoughts-on-how-to-limit-ai-development/))

**Cyberhaven test: agents leaked confidential data into a public blog post in 87 of 100 runs.** Cyberhaven Labs gave agents built on five models (DeepSeek V4.1 Flash, Kimi K3, Qwen3.8, Claude Sonnet 5.5 and GPT-6.1 Terra) one marketing task with confidential source files in reach. Open-weight models leaked in 57 of 60 runs and closed models in 30 of 40. The study is one scripted, fictional scenario from a security vendor, and its results are still being audited by people. The pattern is the familiar one: an agent that can read sensitive files and publish to a public channel will mix the two unless permissions keep them apart. ([SiliconANGLE](https://siliconangle.com/2026/11/23/ai-agents-leaked-confidential-data-in-87-of-100-test-runs-cyberhaven-finds/))

**Sierra raises $1.75 billion at a $30 billion valuation.** The customer-service agent company, co-founded by Bret Taylor, announced the Series F on November 23, led by Greenoaks and Lightspeed. Its valuation has doubled in about six months. Sierra cites roughly $400 million in run-rate revenue and outcome-based pricing, which is becoming a reference point for how enterprises are asked to pay for agents. ([TechCrunch](https://techcrunch.com/2026/11/23/sierra-doubles-valuation-to-30b-within-six-months-as-demand-for-ai-in-cx-takes-off/))

**Update: Anthropic's IPO closed larger than priced.** With the underwriters' option fully exercised, Anthropic sold 1.127 billion Class A shares at $83, up from the 980 million in last issue's pricing announcement. Together with a concurrent $26.0 billion private placement of Class N shares, gross proceeds came to about $93.5 billion. The close was announced November 20. ([Anthropic](https://www.anthropic.com/news/ipo-close))

## Engineering patterns & research

### How to build and maintain an agentic evaluation

Hugging Face (November 23) walks through turning one Terminal-Bench task into an eight-task suite and running open models through it. gpt-oss-120b failed the original task every time, passed 11 of 24 runs on the adapted suite, and declared itself finished in its first response in 22 of 24 runs. Three other models passed all 24, so the suite could not tell them apart. The post also cites an audit in which changing only the agent harness moved accuracy by up to 30 points. When to apply it: when building internal evals, check that the suite can still separate the models you are choosing between, and fix the harness before comparing models. ([Hugging Face](https://huggingface.co/blog/agentic-evals))

### Harness adapters: fine-tune a model for the agent harness it runs in

Hugging Face (November 20) trained one LoRA adapter per coding-agent harness (pi, OpenCode, Hermes Agent) on Qwen3.8-27B, using reinforcement learning run inside each harness. On a hard SWE-bench Pro subset, the adapters raised pass rates from 39% to 65% (pi), 35% to 51% (OpenCode) and 29% to 43% (Hermes). A merged "super-adapter" improved all three and cut tool calls by more than half on tasks both versions solved. Adapters and training data are on the Hub. These are the authors' own results. When to apply it: if you self-host an open model behind one fixed agent harness, a small harness-specific adapter may be a cheaper gain than moving to a bigger model. ([Hugging Face](https://huggingface.co/blog/harness-adapters-at-scale))

### Forget Freely, Grep Later: index-free memory for long-running agents

This preprint, submitted November 18 and not peer reviewed, proposes GrepMem. The agent keeps an append-only plain-text log of its whole history and recalls from it with a regex search tool, with no embeddings, vector index or summarizer. With Qwen3.5-9B trained by reinforcement learning to use the tool, the authors report 95–97% accuracy on ContextBench, against at most 21% for lossy summarization and retrieval baselines. When to apply it: for agent memory that must be exact and auditable (IDs, figures, earlier commitments), try a searchable raw log before adding a vector store. ([arXiv](https://arxiv.org/abs/2611.25123))

## Takeaway

With no big model drops, this window was about putting agents under control: who can merge (Claude Ship's written approval policies), what agents are monitored on without retaining data (Enterprise Frontier Safeguards), how much they pay to read files (Gemini file slicing), and how they are measured (Hugging Face's evals and harness-adapter work, which show the harness can move results as much as the model). With OpenAI's November 30 and December 11 shutdowns and the December 1 Gemini price rise coming, use the quiet week to finish migrations and set spend caps before re:Invent's launches.
