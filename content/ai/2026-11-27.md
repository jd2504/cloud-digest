## Model & platform announcements

### Anthropic

**Claude Opus 4.5 (`claude-opus-4-5-20251101`) is deprecated, retiring January 22, 2027**
- Status: deprecated on November 23, just before the last issue's cutoff, and missed there. The model and its alias `claude-opus-4-5` retire on the Claude API on January 22, 2027. The named replacement is Claude Opus 5.5 (`claude-opus-5-5`), and Anthropic links a migration guide.
- Why it matters: Opus 4.5 is a year old this week and is still pinned in many agent and coding pipelines. Teams have about eight weeks to re-run their evals on Opus 5.5 and update model IDs. Check your Bedrock and Vertex AI deployments as well, since each platform sets its own retirement dates. ([Anthropic deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations); [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview))

**Due Monday, November 30: two Claude API changes take effect**
- Claude Sonnet 4.5 (`claude-sonnet-4-5-20250929`) retires and is replaced by `claude-sonnet-5-5`. From the same day, requests to `claude-opus-4-8` with `speed: "fast"` return an error, and Anthropic points to Opus 5.5 instead. Both were announced earlier and are repeated here because the dates are close. ([Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview))

**Also announced**
- **Organization webhooks add customer-owned storage events (beta).** The new `external_storage.failed` and `external_storage.recovered` events fire when a customer's storage bucket fails or passes Anthropic's daily check. They are for teams that use the zero-data-retention option with Enterprise Frontier Safeguards covered last issue. Alert on them, because a failed bucket breaks your retention setup. (November 23) ([Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview))

### OpenAI

**Healthcare model configurations in the Responses API**
- Status: released November 24 in the API changelog, which gives no GA or preview label. The model IDs are `gpt-6.2-astra-healthcare`, `gpt-6.2-sol-healthcare`, `gpt-6-astra-healthcare` and `gpt-6.1-sol-healthcare`, all on `v1/responses`.
- Availability and pricing: each configuration pairs a model with a harness for clinical questions. When web search is on, it queries a dedicated index of medical sources. The configurations have their own section on the pricing page, separate from the base models. OpenAI's November 16 healthcare post says the computer-use agents in the healthcare API are available only through sales.
- Why it matters: OpenAI now sells healthcare as a domain configuration you call by model ID, not just a base model with a system prompt. On HealthBench Professional, a benchmark OpenAI ran itself, the company reports that GPT-6.2 Astra with this configuration beat Claude Fable 5.2 with web search by 6.3 points and cost about half as much per scored response. Teams building clinical tools should test the configuration against their own retrieval setup and confirm that their BAA covers it. ([OpenAI changelog](https://developers.openai.com/api/docs/changelog); [OpenAI](https://openai.com/index/more-ways-to-move-care-forward-with-chatgpt-for-healthcare/))

**`chat-latest` now points to a newer snapshot**
- Status: updated November 24. The alias follows the latest model in ChatGPT and will keep changing without notice, and OpenAI recommends the GPT-6.2 family for production. If anything in production calls `chat-latest`, pin it to a dated model. ([OpenAI changelog](https://developers.openai.com/api/docs/changelog))

**Due Monday, November 30, and Tuesday, December 1: OpenAI shutdowns**
- November 30: `/v1/prompts` and reusable prompt objects, the Evals dashboard and API, and Agent Builder shut down.
- December 1: `gpt-image-1-mini`, `gpt-image-1.5` and `chatgpt-image-latest` retire, replaced by `gpt-image-2.6-sunburst` or `gpt-image-2.6-flare`.
- Further out, self-serve fine-tuning job creation ends December 15, and `gpt-5`, `o3` and related models retire December 11. All of these were covered earlier. ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations))

### Model platforms

**Microsoft Foundry: shared Toolboxes behind one MCP endpoint**
- Status: described in a Foundry blog walkthrough dated November 21 in the footer and November 25 in the byline. The post gives no GA or preview label and no pricing.
- What it does: a Toolbox is a versioned, centrally managed set of tools that agents reach through one MCP-compatible endpoint. A single Toolbox can mix OpenAPI services, remote MCP servers and built-in Foundry tools such as web search, Foundry IQ, file search, browser automation and A2A. You test a new version at its own endpoint, then promote it, and agents on the stable endpoint pick it up without redeploying. An optional Tool Search mode shows the model only a search tool and pinned tools at first. A Toolbox Monitor reports usage and errors by version.
- Why it matters: this moves tool definitions out of each agent's code into a governed, shared registry, so authentication, versioning and rollback are handled in one place. It works with Microsoft Agent Framework, LangGraph and GitHub Copilot in VS Code. Microsoft says the Toolbox agent used fewer input tokens than an agent with inline tools, but gives no figures. ([Microsoft Foundry Blog](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/from-inline-tools-to-a-shared-toolbox-in-microsoft-foundry/4575475))

### Protocols & open source

**MCP at two years: Events reach beta and the next spec is due March 2027**
- Status: anniversary update from the MCP maintainers, November 24. The post says Events reached beta in November and Skills over MCP is in beta. Enterprise-Managed Authorization is now a stable extension. File uploads and downloads is still a working-group draft. The next specification release is planned for March 2027, following the stateless 2026-07-28 revision.
- Why it matters: the parts enterprises asked for, such as centrally managed authorization and server-pushed events, are now available as extensions instead of custom code. Check which extensions your clients and gateways support before you rely on them. The maintainers report more than 700 million SDK downloads in the 30 days to November 23. ([MCP Blog](https://blog.modelcontextprotocol.io/posts/mcp-turns-two/))

## Engineering patterns & research

### Swarms, Flocks, Gangs: how to train and evaluate multi-agent systems
*Hugging Face blog, November 26.* Ben Burtenshaw and Kashif Rasul argue that most multi-agent gains disappear in a fair comparison, because extra agents also mean extra tokens. Their baselines are a single agent with the same token budget and best-of-N sampling. In their own experiment, they trained four agents that share one Qwen3-0.6B policy to coordinate on a sorting task. Over 75 updates, training success rose from about 7% to 82%, the team used about 37% fewer tokens, and held-out success reached 81%. The run took about five hours on two H200s. **When to apply it:** before adopting a multi-agent design, benchmark it against one agent with the same budget and against best-of-N, and track tokens and messages alongside accuracy. ([Hugging Face](https://huggingface.co/blog/training-swarms))

### How much should an agent remember? Self-distilled memory in production
*arXiv preprint 2611.26361, submitted November 19 and accepted to IAAI 2027. Included here because it was not covered last issue.* IBM researchers describe an agent memory that turns each episode into one to three short lessons. It then merges the lessons into "guidelines" and injects all of them, or a selected subset, at inference time. The system runs in IBM's CUGA agent and watsonx Orchestrate, and the code is open source in the altk-evolve library. On AppWorld, DeepSeek-V3.2 gained 9.5 points of task completion with the full set of 191 guidelines. gpt-oss-120b, a weaker model, did better with about 29 selected guidelines (55.4%) than with all 199 (51.2%). The authors also report failures: one heavily supported guideline backfired, merging silently dropped the source of each lesson, and a swallowed API error failed every task while the logs looked normal. **When to apply it:** tune how much memory you inject for each model rather than using one setting everywhere, and keep the source of every learned rule so a bad one can be traced and removed. ([arXiv](https://arxiv.org/abs/2611.26361))

### Where scientists draw the line on AI agents
*Ai2, via the Hugging Face blog, November 25.* In an exploratory study, Ai2 interviewed 17 US scientists about handing research tasks to agents. Their trust rested on five things: validation, privacy, objectivity, accountability and transparency. They want to control which tasks an agent takes on and how its work is checked. The sample is small and the study measures no agent, so its proposals are design requirements rather than results. Those proposals are full action logs (methods used, files touched), strict data-scope limits, and evals that check whether the agent stayed in scope as well as whether the answer was right. **When to apply it:** use it as a checklist when you build agents for regulated or expert users, especially to log every file and tool the agent touches. ([Hugging Face / Ai2](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents))

## Takeaway

With no new frontier models this week, the job for architects is migration. Claude Opus 4.5 now has a January 22 retirement date. Claude Sonnet 4.5, OpenAI's Prompts, Evals and Agent Builder APIs, and three OpenAI image models all shut down by Tuesday. Pinned aliases like `chat-latest` keep changing underneath callers. The platform news points the same way. Foundry's Toolboxes and MCP's newly stable or beta authorization and events extensions move tools and governance into shared, versioned layers. That makes swapping models less risky, which matters with this many deadlines coming up.
