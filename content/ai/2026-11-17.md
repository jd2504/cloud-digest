## Model & platform announcements

### Anthropic

**Text watermarking now covers older Claude models**
- Status: in effect as of November 16, per the Claude Platform release notes. Output from Claude Opus 4.6, Opus 4.5, Sonnet 4.5 and Haiku 4.5 now carries Anthropic's text watermark on supported platforms. No request changes and no price change.
- How it works: Anthropic describes a variant of Google DeepMind's SynthID-Text. A keyed pattern steers the choice between near-equivalent next tokens, so nothing is added to the text and no user or organization identifiers are embedded. Only a key holder can test for it, and the result is a probability, not proof. It is weak on short text, code and heavily edited output. A detection API is in private preview for regulators, researchers, media and selected enterprises.
- Why it matters: requests that set `temperature`, `top_p` or `top_k` to non-default values may not carry the mark, and the docs warn that client libraries and frameworks sometimes set these for you. If your EU compliance story relies on the provider's marking, check what your SDK sends. The timing lines up with the EU's December 2 deadline for systems placed on the market before August 2 (see Industry & policy). ([Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview); [Claude Platform docs](https://platform.claude.com/docs/en/build-with-claude/text-watermark); [Anthropic](https://www.anthropic.com/news/claude-text-watermark))

### Google

**Gemini 4 Carbon, Google's new top model for agent and coding work (launched November 10; missed in the last issue)**
- Status: GA on Google Cloud's Gemini Enterprise Agent Platform for verified enterprise customers, as `gemini-4-carbon`. On the Gemini API it is available on the paid tier in AI Studio, and Google's post does not give a GA or preview label there. A cyber variant, `gemini-4-carbon-cyber-permissive`, is allowlist-only through Google's Fairwind Program and has no computer use.
- Availability and pricing: Google's announcement and the Cloud model page do not state per-token prices; check the pricing pages before budgeting. On Google Cloud it runs in `global`, `us` and `eu`, with Standard and Priority PayGo, batch and Provisioned Throughput. Context is a unified 1,048,576 tokens shared by input, thinking and output, with a default output budget of 65,536.
- Why it matters: Google reports 61.2% on FrontierSWE 2, 65.2% on Terminal-Bench 4.0 and 81.5% on OSWorld-2.1 (offline subset), and its own table shows GPT-6 Astra and Claude Opus 5.5 ahead on some of these. Migration has sharp edges: `thinking_budget` and the `MINIMAL` level return HTTP 400, temperature and top-p are fixed, explicit context caching is gone (implicit caching applies to prefixes of 4,096+ tokens), and Google Cloud classes it as a "Frontier Model" with abuse monitoring under its service terms. ([Google](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-4-carbon-developers/); [Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/4-carbon); [Google DeepMind model card](https://deepmind.google/models/model-cards/gemini-4-carbon/))

**Gemini Enterprise: user-delegated OAuth for A2A agents is GA**
- Status: GA, November 13.
- What it does: A2A agents built with ADK and deployed on Agent Runtime can now use Agent Identity's auth manager for three-legged OAuth. The platform asks the signed-in user for consent and then calls downstream MCP servers, Google Cloud services or third-party APIs as that user.
- Why it matters: acting on the user's own permissions, rather than a shared service account, is the usual blocker for letting agents touch real business systems. This gives Google-hosted agents a supported way to do it. ([Gemini Enterprise release notes](https://docs.cloud.google.com/gemini/enterprise/docs/release-notes))

**Deadline today: five Gemini audio preview models**
- The earliest shutdown date for `gemini-3.1-flash-live-preview`, `gemini-2.5-flash-native-audio-preview-12-2025`, `gemini-3.1-flash-tts-preview`, `gemini-2.5-flash-preview-tts` and `gemini-2.5-pro-preview-tts` is November 17. Replacements are `gemini-3.8-live` and `gemini-3.8-flash-tts` or `gemini-3.8-flash-lite-tts`. Covered in the last issue; listed again because the date has arrived. ([Gemini API deprecations](https://ai.google.dev/gemini-api/docs/deprecations))

### OpenAI

**CSAM image classifier added to the Moderations API**
- Status: available November 16 to approved organizations, at no cost. Model `omni-moderation-csam-latest` on `v1/moderations`.
- What it does: returns separate signals for potential CSAM and potential AI-generated CSAM, for prioritizing images for human review.
- Why it matters: platforms that accept user-uploaded images can add this as a triage layer next to hash-matching tools without new spend. Access requires approval, so plan lead time. ([OpenAI API changelog](https://developers.openai.com/api/docs/changelog))

No new OpenAI model launches or deprecations were posted in the window. The deadlines noted last issue still stand: `/v1/prompts`, the Evals dashboard and API, and Agent Builder shut down on November 30.

### Model platforms

**Google Cloud: DeepSeek-V4.1-Flash-1017 in preview as a managed model**
- Status: public preview, November 16, in Model Garden as `deepseek-v4.1-flash-1017-maas`.
- Availability and pricing: `global` endpoint only, Standard PayGo only (no Provisioned Throughput or batch). Text and image input, up to 1M tokens of context, with function calling, structured output and thinking. Pricing is on the partner-model pricing page, not the announcement. Google says the endpoint is available until at least December 31, 2026, with extension depending on demand.
- Why it matters: an updated DeepSeek Flash model behind Google Cloud billing and IAM, but the global-only processing and short guaranteed lifetime make it a candidate for evaluation rather than a production dependency. ([Gemini Enterprise Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes); [Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/deepseek/deepseek-v41-flash-1017))

**Amazon Bedrock AgentCore: next-generation runtime is now the default (November 12; missed in the last issue)**
- Status: GA default for new runtimes in 19 Regions. Existing runtimes stay where they are until you set `platformVersion` to `V2`; set `V1` to keep a new runtime on the old version.
- What changed: sessions restore from a snapshot of the initialized agent. AWS says a 2 GB image now starts in under 2 seconds at P75, against 29.7 seconds before. Idle agents scale to zero and release memory within minutes. Each session is still its own Firecracker microVM, now up to 8 vCPU, 32 GB and 10 GB images.
- Why it matters: AWS reports up to 68% less billed memory per session for multi-turn agents, so long-lived, mostly idle agent sessions get cheaper without code changes. Test the switch on existing runtimes before migrating them. ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/new-agentcore-runtime-default/))

Microsoft Foundry posted nothing new in the window; Ignite announcements land from today.

## Industry & policy news

**FBI and AWS warn that AI agents are being used to steal model API keys at scale.** An FBI flash alert dated November 13 and an Amazon Threat Intelligence post the same day describe campaigns run with ARTEX, an open-source agentic penetration-testing framework. Amazon's honeypots, posing as LLM inference APIs, captured agents whose memory showed them stealing AI-service and cloud keys and then using those keys to run more agents hunting for keys. Targets included LiteLLM, One API, Dify, Langflow, Ollama and Open WebUI, through default master keys, unauthenticated admin endpoints, known CVEs and SSRF to cloud metadata. The Register reports that Censys counted 1,465 exposed ARTEX consoles as of November 4. For architects: model gateways and inference endpoints now need the same controls as production databases, and unexpected AI spend is a security signal. ([The Register](https://www.theregister.com/cyber-crime/2026/11/16/attackers-are-using-ai-agents-to-automate-cybercrime-at-industrial-scale-fbi-and-aws-warn/5310223); [AWS Security Blog](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-observes-threat-actors-running-cybercrime-campaigns-with-artex-ai-agents/))

**EU AI Act: the December 2 marking deadline is two weeks out.** Article 50 transparency obligations have applied since August 2, 2026. The Commission's FAQ says generative systems placed on the market before that date have until December 2, 2026 to meet the machine-readable marking and detection duty, and that deployers must still visibly disclose deepfakes, since embedded marks alone don't satisfy that duty. The Commission's pages are not fully consistent on whether the Digital Omnibus grace period and the adequacy assessment of the voluntary transparency Code of Practice are final, so confirm with counsel. Anthropic's extension of watermarking to pre-August models this weekend is one provider's answer. ([European Commission](https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act); [European Commission](https://digital-strategy.ec.europa.eu/en/faqs/code-practice-transparency-ai-generated-content))

**Anthropic shortens its vulnerability disclosure deadlines.** From January 1, 2027, Anthropic's coordinated disclosure policy for bugs it reports to vendors and maintainers drops from 90 days to 30 for high and critical severity, and to 45 days for everything else. Escalation to an outside coordinator after no response moves from 30 days to 15. The seven-day window for actively exploited bugs is unchanged, and AI-found issues without human review are excluded. If you maintain software that Anthropic's Frontier Red Team scans, expect less time to patch. ([Anthropic](https://www.anthropic.com/research/coordinated-vulnerability-disclosure-timelines))

**OpenAI will embed Apollo Research evaluators to test for model subversion.** TechCrunch reports that Apollo said on November 16 that six of its evaluators will work inside OpenAI in a pilot testing whether models try to undermine alignment or control mechanisms for themselves or their successors. Under the terms Apollo described, OpenAI can withhold some information and limit the evidence Apollo publishes, though it agreed not to withhold material just because it is unfavorable. TechCrunch says OpenAI had not commented and no start date was given. This matters for teams relying on third-party safety evaluations in vendor risk reviews: read the access terms behind any such evaluation. ([TechCrunch](https://techcrunch.com/2026/11/16/openai-will-embed-apollo-researchers-to-investigate-ai-subversion/))

## Engineering patterns & research

### Stage-based routing between a cheap and a capable model for coding agents
Source: [AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/route-coding-agent-requests-to-the-right-model-on-amazon-bedrock-with-nvidia-nemo-switchyard/) (November 13). AWS shows NVIDIA NeMo Switchyard as a LiteLLM plugin in front of Bedrock: every agent request goes to a model alias, starts on the efficient model (Nemotron 3 Super 120B in the sample), and escalates to the capable one (Claude Opus 5.5) based on the last three tool results rather than on a judge model. A weighted random mode supports A/B tests, and a response header records which model answered. The metric is cost per solved task, meaning total spend divided by runs whose tests pass. The code is sample-grade and the post publishes no results. Apply it when coding-agent spend is dominated by routine turns, and measure escalation replay costs before trusting the savings.

### Measure agents by cost per successful task, not cost per token
Source: [AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/optimizing-cost-per-task-and-proving-agent-roi-on-amazon-bedrock/) (November 12, just before this window; not covered previously). The post defines cost per successful task as cost per attempt divided by success rate, with a variant for escalate-on-failure designs. It names four hidden cost drivers: tokenizer efficiency, output verbosity, the number of agent loop turns (each one re-sends context) and reasoning tokens billed as output. It recommends prompt caching as the biggest lever on agent paths, capping output with tool schemas and `maxTokens`, and leaving extended thinking off unless a benchmark justifies it. It also gives a five-dimension ROI scorecard measured against a documented human baseline. Use it when you need to defend an agent's budget, or to compare models whose per-token prices mislead.

### Rules engine plus feedback-memory RAG for a legal review agent (Uber)
Source: [InfoQ](https://www.infoq.com/news/2026/11/uber-legal-redlining-agent/) (November 16), reporting Uber Engineering's post. Uber's contract redlining agent runs as a Word add-in on a LangGraph backend, with parallel nodes for intent, risk and policy lookup. A deterministic rules engine overrides the model whenever a non-negotiable rule matches. Playbook-only RAG struggled, so Uber added retrieval over lawyers' past decisions and edits: similarity search narrows to about 20 candidates, a model re-ranks them, and a 365-day half-life favors recent precedent. Uber reports review time down more than 20% and 91% decision accuracy, without published method. Apply this split, with hard rules in code and judgment in the model plus retrieved precedent, in any regulated workflow where some answers must never vary.

## Takeaway

With few launches this weekend, the signal is in governance and security plumbing. Anthropic brought older Claude models under its text watermark ahead of the EU's December 2 deadline, and the FBI and AWS documented AI agents harvesting model API keys from exposed LLM gateways. Before the next model release, confirm that your SDK's sampling settings don't strip provider watermarks, and treat model keys and gateways as production credentials and infrastructure.
